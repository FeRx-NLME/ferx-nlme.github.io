Simulation-based NPDE / NPD diagnostics from a fit

Description

Computes Normalized Prediction Distribution Errors (NPDE, decorrelated within subject) and Normalized Prediction Discrepancies (NPD) post-hoc by Monte-Carlo simulation under the fitted model (Brendel et al. 2006; Comets et al. 2008). Use this when a model was fitted without [fit_options] npde_nsim and you want the diagnostics without re-running [ferx_fit](ferx_fit.qmd). Unlike CWRES, NPDE/NPD are robust to model nonlinearity and non-Gaussian random effects, and follow N(0, 1) under a correctly specified model.

Usage

ferx_calc_npde(fit, nsim = 1000L, seed = NULL, model = NULL, data = NULL)

Arguments

  • fit: A ferx_fit result, carrying theta, omega, sigma, and (unless overridden) the model_path / data_path captured at fit time.
  • nsim: Number of Monte-Carlo replicates per subject (default 1000). NPDE needs nsim greater than each subject’s observation count for a full-rank simulated covariance; subjects that fail this get NA NPDE (NPD is still computed).
  • seed: Optional integer RNG seed for reproducibility. NULL (default) uses the engine’s built-in default seed.
  • model: Path to the .ferx model file. Defaults to fit$model_path.
  • data: Path to the NONMEM-format CSV, or a data.frame (see [ferx_fit](ferx_fit.qmd)). Defaults to the fit’s own data.

Details

The data are re-read with the selection the fit was made with (fit$reader_settings): a ferx_fit(ignore =, accept =, ignore_ids =) selection applies as well as the model file’s [data_selection], also to a file passed as data. On a model passed as model, only the fit’s selection is replayed: that file’s own [data], [covariates] and iov_column decide how the data are read. A fit made before the selection was recorded is refused when its fit$exclusions show a clause, or its fit$call_settings an iov_column, that the model file does not state; that model file (model, or fit$model_path, which must still have the fit’s hash) is the one compared. When the model and data are the fit’s own (model and dataleft NULL, or naming fit$model_path / fit$data_path), the re-read data are checked against the fit’s fit$population_fingerprint, as [ferx_covariance](ferx_covariance.qmd) and [ferx_sir](ferx_sir.qmd) check theirs: a data file edited since the fit is refused with code E_POPULATION_MISMATCH, saying what differs.

Errors raised by the engine

A model or dataset the engine refuses is an R error, never a NULLresult. Where the engine’s validation pass names the finding, the error has class ferx_engine_error and carries code, block, line and suggestion - the same condition a refused [ferx_fit](ferx_fit.qmd) raises, so one tryCatch(..., ferx_engine_error = ) handler covers every entry point. Its message ends with the code in square brackets and, when there is a suggestion, a hint: ... line, as a refused fit’s does. A failure the validation pass cannot attribute to one diagnostic is raised as an ordinary error carrying the engine’s message.

Theta level blocks

A theta NAME[COL, ...] level block has one theta per combination of the columns observed in the data it is bound to. With a fit, the design in data is placed on the fit’s levels, recorded in fit$theta_levels: each design record reads the theta its level was estimated under, whatever order or subset of the fit’s levels the design holds. A design level the fit never observed is refused, naming every such level, because no theta was estimated for it. In particular:

  • A block keyed on TIME can be simulated only at the fit’s observation times. Use the fit’s own data as the VPC design; a denser or different time grid has no fitted theta.
  • A study the fit never saw cannot be simulated with fitted level thetas.
  • A block whose columns do not include TIME is unaffected by the time grid.

Without a fit, the design’s own levels are bound and the model’s initial values are used. A fit without theta_levels (one made, or a .fitrx saved, before ferx recorded them) is refused on a level-block model; refit it with [ferx_fit](ferx_fit.qmd).

Concept

simulation

Value

A new fit with new bytes, the input fit being left as it was, with NPDE and NPD columns added to its sdtab data frame (replacing any existing ones). They are in the fit’s bundle, so they survive [ferx_save_fit](ferx_save_fit.qmd). A fit with no bundle, such as one from an .rds written by an older ferx, is refused with an error of class ferx_no_bundle_error: refit it. Because the diagnostics live in fit$sdtab, downstream consumers such as [ferx_xpose](ferx_xpose.qmd) and goodness-of-fit plots pick them up automatically.

Examples

ex  <- ferx_example("warfarin")
fit <- ferx_fit(ex$model, ex$data, method = "gn", covariance = FALSE)
fit <- ferx_calc_npde(fit, nsim = 1000L, seed = 12345L)
head(fit$sdtab[, c("ID", "TIME", "NPDE", "NPD")])
