Run the covariance step against an existing fit

Description

Run the standard-error covariance step against a fit that was produced earlier - the covariance-step analogue of [ferx_sir](ferx_sir.qmd). Useful when the original fit was expensive and you want to add standard errors without re-estimating, when you want to re-run the step with a different covariance_method (e.g. the rsr sandwich), or when working with a fit loaded from a .fitrx bundle.

Usage

ferx_covariance(
  fit,
  covariance_method = NULL,
  mu_referencing = NULL,
  verbose = FALSE,
  threads = NULL
)

Arguments

  • fit: A ferx_fit object produced by [ferx_fit](ferx_fit.qmd) or [ferx_load_fit](ferx_load_fit.qmd).
  • covariance_method: Covariance estimator. NULL (the default) replays the fit’s own: fit$call_settings$covariance_method, else the model file’s [fit_options], else the engine default "r", asked for as the fit asked for it. Otherwise "r" (inverse Hessian, NONMEM MATRIX=R), "s" (inverse cross-product, MATRIX=S), or "rsr" (the Huber-White sandwich, MATRIX=RSR), which overrides the fit’s; "hessian" / "cross_product" / "sandwich" are accepted as aliases. Passed explicitly, "r" is held to even above the size at which the engine routes a defaulted "r" on finite differences onto "s", as ferx_fit(settings = list(covariance_method = "r")) is. Before ferx-r #659 the default was "r".
  • mu_referencing: Use mu-referencing for the inner-loop warm restart. NULL (the default) takes the fit’s recorded value (fit$scoring_settings$mu_referencing), else TRUE. TRUE or FALSE overrides the record for this call.
  • verbose: When TRUE, the engine prints progress to stderr. Default FALSE.
  • threads: Worker threads the step runs on. NULL (the default) takes the width the fit ran on, fit$n_threads_used; 0 asks for the engine default; a positive integer pins the width. It does not change the result, only the resources the step uses. The returned fit’s n_threads_used reports the width this step ran on.

Details

ferx_covariance() runs on the fit’s bundle (fit$bundle), the bytes the engine serialized it to: it reads the fit from them, re-runs the inner loop to rebuild the covariance-step inputs, and calls the same covariance step [ferx_fit](ferx_fit.qmd) runs inline. It returns a new fit with new bytes, in which cov_matrix, cor_matrix, se_theta / se_omega / se_sigma / se_kappa, covariance_status, eigenvalues, and condition_numberare refreshed. The input fit is not altered. A change made to the fit’s list by hand does not reach the step, and a fit with no bundle, such as one from an .rds written by an older ferx, is refused with an error of class ferx_no_bundle_error: refit it. The model and data files are the ones at fit$model_path and fit$data_path, checked against the hashes in the bytes. A covariance step that runs but cannot produce a usable matrix (a non-positive-definite or structurally-unusable covariance Hessian, from the analytic R-matrix or the FD stencil alike) is not an error: the returned fit reports covariance_status = "failed" with a diagnostic appended to warnings, mirroring [ferx_fit](ferx_fit.qmd). An error is reserved for input problems (missing / hash-mismatched model or data, or a fit whose parameters do not match the model, such as a kappa model whose fit carries no omega_iov). A fit with a profile theta level block (fit$profiled_blocks) takes all three methods (ferx-core #2108). "rsr" is the unprofiled sandwich with the profiled R^-1; "s" is S^-1 over every parameter, levels included, and still needs more subjects than free parameters. A profiled level the fit holds on its declared bound (fit$profiled_levels_at_bound, ferx-core #2112) is held by the step too, as a FIX theta is: it gets no standard error, and the others are computed with it held. The step rebuilds that list from the estimates and the bound, so the returned fit carries this step’s.

Settings

The step scores the objective under the inner-loop and ODE settings the fit recorded as fit$scoring_settings (the stage that produced the estimates: inner_maxiter, inner_tol, inner_optimizer, mu_referencing, ode_reltol, …), and starts from the optimizer’s exact estimate fit$packed_estimate. With both, ferx_covariance(fit) is identical() to the covariance ferx_fit(..., covariance = TRUE) reports, unless a covariance_method other than the fit’s is passed. That holds on every estimation method with an in-fit step, with or without kappa (IOV): the step is taken for the fit’s own method (fit$method), and Gauss-Newton, SAEM, importance sampling and VI start from the EBEs the fit reports - fit$ebe_etas and, under IOV, fit$ebe_kappas - which their own warm-started solves produced (ferx-core #1847, ferx-r #591). The method matters beyond the objective: at an SAEM, importance-sampling or VI estimate, an R matrix that needs an eigenvalue floor is replaced by S^-1 (warning W_COV_NON_STATIONARY_ESTIMATE), as the in-fit step does. The step’s own settings are the fit’s too: covariance_method (unless passed), fd_hessian_step, analytic_cov_hessian and cov_inner_tol, as the fit was given them - the model file’s [fit_options], overridden by ferx_fit()’s argument or settings (recorded in fit$call_settings). The engine does not record them, so a fit made with fd_hessian_step = 0.1 used to be replayed at the default step, and a profiled fit made with fd_hessian_step = 0.01 at the profiled default 3e-3 (ferx-core #2414). The model file’s values are read from the model file itself, so a bundle written by ferx-core, which carries no fit$call_settings, keeps them; only call-time overrides need the R record. Until ferx-r #659 covariance_method defaulted to "r" whatever the fit ran, so a fit made with settings = list(covariance_method = "rsr"), or with covariance_method = rsr in [fit_options], was replayed as "r" unless the caller repeated it. The estimator a step ran is recorded as fit$covariance_method (NA when it produced no matrix), and is kept by [ferx_save_fit](ferx_save_fit.qmd) / [ferx_load_fit](ferx_load_fit.qmd). A replay of the fit’s own method that runs another estimator than the recorded one warns, naming the method to pass. A fit whose step produced a matrix but recorded no estimator, such as a bundle saved before #659, is replayed from its call settings, then the model file’s [fit_options], then "r"; when it falls back to "r"because neither records a method, a message says so. A fit loaded with [ferx_load_fit](ferx_load_fit.qmd) keeps both, so its result is identical() to the in-fit one too. A fit loaded from a bundle saved before packed_estimate was recorded differs from the in-fit one in the last digits (on warfarin_iov, about 1e-7 relative in the standard errors), and so does a Gauss-Newton / SAEM / importance-sampling / VI fit loaded from a bundle ferx-core wrote with six-decimal EBEs (before ferx-core #1847): the step restarts it from a cold solve. A fit whose estimates were edited after the fit does not use packed_estimate. A fit with no scoring_settings (a bundle saved before they were recorded) is scored with the engine’s defaults, as before. A [mixture] fit with per-class overrides reads them from fit$mixture_overrides (ferx-core #1765), else from packed_estimate; the step refuses one that carries neither, such as an SAEM mixture fit loaded from a bundle saved before either was recorded. The record includes the gradient route the fit took (fit$scoring_settings$gradient_method): a fit made with gradient = "fd"is differentiated by finite differences here too, with default arguments and after a reload.

Data selection

The data are re-read with the selection the fit was made with, recorded as fit$reader_settings: a ferx_fit(ignore =, accept =, ignore_ids =)selection applies as well as the model file’s [data_selection], and the engine checks the rows it reads against fit$population_fingerprint. A fit made before these were recorded is refused when its fit$exclusions show a clause, or its fit$call_settings an iov_column, that the model file does not state, rather than scored on other data.

Integrity check

Like [ferx_sir](ferx_sir.qmd), ferx_covariance() re-reads the model and data files recorded on the fit (fit$model_path, fit$data_path) and verifies their SHA-256 hashes (fit$model_hash, fit$data_hash); if either file changed since the fit, the call is a hard error. Running the covariance step against a modified model or dataset would be meaningless. Edge case: if hashing failed at fit time the corresponding fit$*_hash is NA and the integrity check silently passes on that side. Check !is.na(fit$model_hash) && !is.na(fit$data_hash) before relying on the protection.

Concept

fitting

Value

A new fit with new bytes, the input fit being left as it was, with cov_matrix, cor_matrix, se_theta, se_omega, se_sigma, se_kappa, covariance_status, covariance_method (the estimator this step ran), eigenvalues, condition_number, max_abs_correlation (the largest absolute off-diagonal parameter correlation, NA when the step produced no matrix - the value [check_strictness](check_strictness.qmd) gates on), the se column of residual_correlations, n_threads_used (the width this step ran on) and covariance_wall_time_secs (this step’s wall-clock time) refreshed.

Examples

ex  <- ferx_example("warfarin")

# Fit without the covariance step, then add it post-hoc.
fit <- ferx_fit(ex$model, ex$data, covariance = FALSE)
fit <- ferx_covariance(fit)
fit$se_theta       # standard errors now populated
fit$cov_matrix     # parameter covariance matrix

# Re-run with the robust sandwich estimator instead.
fit_rsr <- ferx_covariance(fit, covariance_method = "rsr")
fit_rsr$se_theta
